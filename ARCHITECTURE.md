# Architecture

This document describes the current ownership model. It is intentionally free of migration
stages, dated evidence, and historical status claims. Architecture checks derive their result from
the source tree and the active contracts under `fixtures/contracts/`.

## Kotlin modules

- `domain` owns platform-neutral models, repository contracts, and use cases. It has no Android,
  persistence, networking, DI, or generated-native dependencies.
- `data` implements domain contracts and owns persistence, workspace/session lifecycle, SAF,
  Keystore and WorkManager integration. It is the sole production consumer of generated
  `native-bindings` (`com.lomo.nativebridge`). All workspace, store, sync and LAN calls use the
  single managed engine session.
- `app` owns navigation, screen state, and product composition. It depends on domain contracts,
  not native bindings or data implementation types.
- `ui-components` owns reusable presentation components and has no business or platform owner.
- `native-bindings` is generated Kotlin/JNI declarations. It is ignored by Git and regenerated by
  `lomo-xtask`; it contains no business logic.

## Rust crates

- `lomo-core` owns platform-independent engine, identity, lock, journal, cancellation and event
  protocols.
- `lomo-workspace` is the sole Markdown/document/render/patch authority.
- `lomo-store` is the sole local persistence and projection authority.
- `lomo-media` owns media identity and lifecycle operations.
- `lomo-sync` is the sole remote-sync planner and state-machine owner for Git, WebDAV and S3.
- `lomo-git` is the only `git2` adapter and implements provider ports without owning planning.
- `lomo-lan` owns pairing, trust, wire protocol, journals, resume and transfer commit fences.
- `lomo-native` is the only business FFI facade. It performs DTO conversion and composes the
  managed Rust owners at the JNI boundary.
- `lomo-xtask` is tooling only and is the sole public quality/build orchestrator.

Dependencies point inward: domain-independent crates do not depend on Android, JNI, BoltFFI,
SQLite backends, provider SDKs, or tooling. The native facade depends on owner crates and is the
only FFI boundary. Generated bindings and packaged native libraries are build outputs, never
versioned facts.

## Platform boundaries

SAF, DocumentsContract, Keystore, WorkManager, Android networking snapshots, notifications and
Compose remain explicit platform exceptions owned by `data`/`app`. Provider protocols, workspace
bytes, revisions and mutation fences remain Rust-owned. No Room, JGit, Kotlin Markdown parser,
Kotlin sync planner, duplicate writer, compatibility flag, NoOp fallback, or legacy FFI transport
is allowed in the production graph.

## Contracts and routing

Stable behavior contracts live in `fixtures/contracts/`; executable safe-behavior and performance
inputs live in `fixtures/baselines/`. Markdown, remote-provider and characterization fixtures are
retained when consumed by current tests. Changes route to the owning module above, with tests at
the narrowest owner boundary. Quality gates are defined in `quality/README.md`; real provider,
SAF, signing, capacity and device checks may remain `pending_env` when the environment is absent.

## Long-term decisions

| Decision | Owner/boundary |
| --- | --- |
| One managed engine/session and one writer | `data` session + Rust owner crates |
| One Markdown, store, sync and LAN authority | `lomo-workspace`, `lomo-store`, `lomo-sync`, `lomo-lan` |
| One FFI facade and generated binding package | `lomo-native` -> `native-bindings` |
| Pinned Rust 1.97 quality entry | `rust/rust-toolchain.toml` + `lomo-xtask` |
| Generated outputs are rebuilt, not tracked | xtask packaging and `.gitignore` |
